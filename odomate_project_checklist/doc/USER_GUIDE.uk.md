## 1. Що робить цей модуль

Багато завдань щоразу виконуються за тим самим сценарієм: підключення клієнта, запуск вебсайту, звільнення працівника. Модуль дозволяє адміністратору проєктів один раз описати такий сценарій як **шаблон чек-листа**. Той, хто працює над завданням, обирає чек-лист, і його кроки копіюються в завдання. Кожен крок має статус, завдання показує індикатор прогресу, а дати початку й завершення заповнюються самі.

| Можливість | Деталі |
|---|---|
| Багаторазові шаблони | **Project → Configuration → Checklists** (Проєкт → Налаштування → Чек-листи): назва, опис і впорядкований список кроків. Кожен крок має назву та необов'язкову примітку. |
| Застосування в один клік | Вибір шаблону в полі **Checklist** (Чек-лист) завдання копіює всі його кроки в завдання. |
| Незалежна копія в кожному завданні | Кроки завдання можна редагувати, переставляти, додавати й видаляти. Подальші зміни шаблону **ніколи** не змінюють чек-листи, уже застосовані до завдань. |
| Статуси кроків | **To Do → In Progress → Done** (До виконання → У роботі → Виконано) або **Cancelled** (Скасовано). У кожному рядку є кнопки **Start**, **Done**, **Cancel**. |
| Індикатор прогресу | Виконані кроки ÷ (усі кроки − скасовані) × 100. Показується у формі завдання та як стовпець у списку завдань. |
| Автоматичні дати | **Start Date** (Дата початку) заповнюється, коли перший крок розпочато або виконано. **End Date** (Дата завершення) заповнюється, коли чек-лист досягає 100%, і очищується, якщо прогрес знижується. |
| Безпечна заміна | Коли роботу вже розпочато, перехід на інший чек-лист відбувається через діалог підтвердження, який показує, що саме буде втрачено. |

## 2. Де знайти його в Odoo

Модуль не має власного головного меню. Він доповнює стандартний застосунок **Project** (Проєкт):

- **Project → Configuration → Checklists**: створення й підтримка шаблонів чек-листів.
- **Форма завдання**:
  - поле **Checklist** одразу після **Tags** (Мітки)
  - поля **Start Date** та **End Date** одразу після **Deadline** (Крайній термін)
  - вкладка **Checklist** у нотатнику (з'являється, щойно в завданні є хоча б один крок)
- **Список завдань**: стовпець **Checklist Progress** (Прогрес чек-листа) з індикатором.
- **Пошук завдань**: фільтр **With Checklist** (З чек-листом) і пошук за полем **Checklist**.

> 💡 У стандартному Odoo меню **Project → Configuration** бачать лише адміністратори проєктів. Інші користувачі все одно можуть переглядати шаблони й обирати їх у завданнях, але не бачать меню налаштувань.

## 3. Початкове налаштування: створення шаблону чек-листа

**Шлях:** `Project` → `Configuration` → `Checklists` → `New` (Створити)

| Поле | Що вводити | Приклад |
|---|---|---|
| **Name** (Назва, обов'язкове) | Назва, яку користувачі обиратимуть у завданні | `New Client Onboarding` |
| **Description** (Опис) | Для чого призначений чек-лист (внутрішня примітка) | `Стандартні кроки підключення нового клієнта` |
| **Steps Count** (Кількість кроків) | Лише для читання. Кількість кроків у шаблоні | `5` |
| Вкладка **Steps** (Кроки) | Один рядок на крок: **Name** (обов'язкове) і необов'язкова **Note** (Примітка). Щоб змінити порядок, перетягуйте за маркер (⋮⋮) ліворуч. | `Create Account`, `Send Welcome Email`, `Schedule Kick-off Call`, `Set Up Shared Folder`, `Confirm First Invoice` |

Список **Checklists** показує **Name** і **Steps Count** кожного шаблону. Шаблони можна шукати за назвою або за полем **Step** (Крок), щоб знайти всі шаблони з певним кроком, наприклад «Invoice».

Щоб перестати пропонувати шаблон, не видаляючи його, **архівуйте** його (меню дій ⚙ → **Archive**). Архівовані шаблони зникають зі списку вибору поля **Checklist**. Завдання, які вже їх використовують, зберігають свої кроки. Знайти архівовані шаблони можна фільтром **Archived**.

> 💡 Якщо завантажено демо-дані, є три зразкові шаблони: *New Client Onboarding* (5 кроків), *Website Launch Checklist* (4 кроки) та *Employee Offboarding* (4 кроки).

## 4. Застосування чек-листа до завдання

1. Відкрийте будь-яке завдання (**Project → Projects → *ваш проєкт* → *завдання***).
2. У полі **Checklist** (поруч із **Tags**) оберіть шаблон, наприклад `New Client Onboarding`.
3. Збережіть. Усі кроки шаблону копіюються в завдання зі статусом **To Do**, і з'являється вкладка **Checklist**.

Що можна робити з копією в завданні:

- **Редагувати** назву чи примітку кроку під це завдання.
- **Змінювати порядок** кроків перетягуванням.
- **Додавати** кроки через *Add a line* (Додати рядок) унизу списку.
- **Видаляти** кроки, які не стосуються завдання.

Жодна з цих дій не впливає на шаблон. І навпаки: якщо адміністратор згодом перейменує, додасть або видалить кроки в шаблоні, завдання, які вже його використовують, збережуть свої кроки без змін. Нову версію отримають лише завдання, до яких шаблон застосують після цього.

> 💡 Поки жоден крок не розпочато, не виконано й не скасовано, можна просто обрати інший шаблон у полі **Checklist**. Кроки заміняться без діалогу, бо роботу ще не розпочато. Якщо роботу вже розпочато, див. [розділ 8](#8-заміна-чек-листа-робота-над-яким-уже-почалася).

## 5. Робота з кроками

Відкрийте вкладку **Checklist** завдання. Угорі показано індикатор **Checklist Progress**, під ним список кроків:

| Стовпець | Значення |
|---|---|
| ⋮⋮ (маркер) | Перетягніть, щоб змінити порядок |
| **Name** | Крок |
| **Note** | Необов'язкові інструкції, скопійовані з шаблону |
| **Status** (Статус) | Кольоровий жирний текст: **To Do**, помаранчевий **In Progress**, зелений **Done**, червоний **Cancelled**. Клацніть, щоб вибрати статус вручну (для виправлення помилки). |
| Кнопки | **Start** (▶ Почати), **Done** (✓ Виконано), **Cancel** (✕ Скасувати). Показуються лише кнопки, доречні для поточного статусу. |

**Переходи статусів:**

| Поточний статус | Доступні кнопки | Результат |
|---|---|---|
| To Do | **Start**, **Done**, **Cancel** | In Progress / Done / Cancelled |
| In Progress | **Done**, **Cancel** | Done / Cancelled |
| Done | немає | щоб повернути, змініть **Status** вручну |
| Cancelled | немає | щоб повернути, змініть **Status** вручну |

Щоб скасувати випадкове натискання (наприклад, крок помилково позначено **Done**), клацніть клітинку **Status** і виберіть правильне значення, наприклад **To Do**. Прогрес і End Date перераховуються одразу.

Рядки також підсвічуються кольором: **зелений** для виконаних, **червоний** для скасованих, **помаранчевий** для кроків у роботі.

Кожен крок також зберігає, коли його вперше розпочали (**Started On**) і коли виконали (**Done On**). Ці дані зберігаються для довідки й не показуються у формі завдання.

## 6. Як розраховується прогрес

```
Checklist Progress = Виконані кроки ÷ (Усі кроки − Скасовані кроки) × 100
```

Скасовані кроки повністю виключаються з розрахунку, тож скасування нерелевантного кроку не знижує показник. Якщо придатних кроків немає (кроків немає взагалі або всі скасовані), прогрес дорівнює **0%**.

**Приклади розрахунку**

| Кроків | Виконано | У роботі | До виконання | Скасовано | Розрахунок | Прогрес |
|---|---|---|---|---|---|---|
| 5 | 2 | 1 | 2 | 0 | 2 ÷ 5 | **40%** |
| 5 | 2 | 0 | 2 | 1 | 2 ÷ (5 − 1) = 2 ÷ 4 | **50%** |
| 4 | 2 | 0 | 1 | 1 | 2 ÷ (4 − 1) = 2 ÷ 3 | **67%** |
| 3 | 2 | 0 | 0 | 1 | 2 ÷ (3 − 1) = 2 ÷ 2 | **100%** |
| 3 | 0 | 0 | 0 | 3 | немає придатних кроків | **0%** |

Кроки «У роботі» ще не вважаються виконаними. Вони враховуються в прогресі лише після позначення **Done**.

## 7. Start Date та End Date

Модуль додає до завдання два **нові** поля дат, які показуються як **Start Date** (Дата початку) та **End Date** (Дата завершення) одразу після **Deadline** (технічні назви `checklist_date_start` і `checklist_date_end`).

> ℹ️ **Чому нові поля?** Стандартна модель `project.task` уже має технічне поле `date_end` (дата й час), яким керує ядро Odoo. Щоб не втручатися в стандартну поведінку, модуль не записує в нього, а веде власні дати чек-листа.

| Поле | Заповнюється автоматично, коли… | Очищується автоматично, коли… | Ручне редагування |
|---|---|---|---|
| **Start Date** | крок уперше переходить у **In Progress** або **Done**, **і** поле порожнє. Встановлюється сьогоднішня дата. | ніколи. Після встановлення автоматично не змінюється. | ✅ Завжди |
| **End Date** | прогрес досягає **100%** (є хоча б один нескасований крок) **і** поле порожнє. Встановлюється сьогоднішня дата. | прогрес падає нижче 100% (наприклад, додано новий крок або крок повернуто в невиконаний стан), **або** чек-лист замінено через діалог **Replace Checklist** | ✅ Завжди |

**Приклад хронології** (шаблон із 4 кроків):

| Дата | Дія | Прогрес | Start Date | End Date |
|---|---|---|---|---|
| 2 бер. | Чек-лист застосовано | 0% | – | – |
| 3 бер. | Крок 1 → **Start** | 0% | **3 бер.** | – |
| 5 бер. | Крок 1 → **Done**, крок 3 → **Cancel** | 1 ÷ 3 = 33% | 3 бер. | – |
| 9 бер. | Кроки 2 і 4 → **Done** | 3 ÷ 3 = 100% | 3 бер. | **9 бер.** |
| 10 бер. | Додано новий крок «Client sign-off» | 3 ÷ 4 = 75% | 3 бер. | *очищено* |
| 12 бер. | «Client sign-off» → **Done** | 100% | 3 бер. | **12 бер.** |

Примітки:
- Якщо ви ввели Start Date чи End Date вручну, автоматика не перезапише її сьогоднішньою датою. Виняток: End Date однаково очищується, щойно будь-який крок змінює статус, поки прогрес нижчий за 100%.
- Заміна чек-листа **не** очищує Start Date, бо роботу над завданням уже було розпочато.

## 8. Заміна чек-листа, робота над яким уже почалася

Щойно **будь-який** крок має статус In Progress, Done або Cancelled, поле **Checklist** стає лише для читання, а під ним з'являється кнопка **Replace Checklist** (⇄ Замінити чек-лист). Це захищає виконану роботу від випадкової зміни у списку вибору.

1. Натисніть **Replace Checklist**. Відкриється діалог із полями **Task** (Завдання) та **Current Checklist** (Поточний чек-лист).
2. Оберіть **New Checklist** (Новий чек-лист). Поточний шаблон у списку не пропонується.
3. Прочитайте попередження. Воно показує, що саме буде втрачено, наприклад: *"5 current step(s) (2 done, 1 in progress, 1 cancelled) will be deleted and replaced by the steps of "Website Launch Checklist". The End Date will be cleared."* (5 поточних кроків (2 виконано, 1 у роботі, 1 скасовано) буде видалено й замінено кроками «Website Launch Checklist». End Date буде очищено.)
4. Натисніть **Replace Checklist**, щоб підтвердити. Усі поточні кроки видаляються, кроки нового шаблону копіюються зі статусом **To Do**, а **End Date** очищується. **Start Date** зберігається.
   Або натисніть **Discard** (Відхилити), щоб закрити діалог. Нічого не зміниться.

> ℹ️ **Чому кнопка, а не спливне вікно під час зміни поля?** В Odoo зміна поля у формі (так званий onchange) не може відкрити діалог підтвердження без власного JavaScript, а цей модуль свідомо створено без власного JavaScript. Тому поле блокується, щойно роботу розпочато, а заміна виконується через цей явний діалог. Якщо змінити чек-лист іншим способом (наприклад, імпортом), Odoo відхилить дію з повідомленням: *"The checklist of task … is already in progress. Use the Replace Checklist button to switch to another checklist."*

## 9. Список завдань і пошук

- **Стовпець Checklist Progress**: у списку завдань (наприклад, **Project → Projects → *проєкт*** у режимі списку) показано індикатор прогресу для кожного завдання. Стовпець необов'язковий, його можна показати або приховати через вибір стовпців. Під час групування рядок групи показує **середній** прогрес.
- **Фільтр With Checklist** (у розділі Filters панелі пошуку): лише завдання, що мають хоча б один крок чек-листа.
- **Пошук за Checklist**: введіть назву шаблону в рядку пошуку й оберіть *Search Checklist for: …*, щоб знайти всі завдання з цим шаблоном.

## 10. Ролі доступу

| Роль | Шаблони чек-листів (та їхні кроки) | Кроки чек-листів у завданнях | Діалог Replace Checklist |
|---|---|---|---|
| **Внутрішній користувач** (`base.group_user`) | ✅ Лише читання (може обирати шаблони в завданнях) | ✅ Читання / створення / редагування / видалення, **лише в завданнях, які він бачить** (див. нижче), у межах дозволених компаній | ✅ Може використовувати |
| **Адміністратор проєктів** (`project.group_project_manager`) | ✅ Читання / створення / редагування / видалення | ✅ Читання / створення / редагування / видалення в **усіх** завданнях дозволених компаній | ✅ Може використовувати |

**Які кроки бачить і редагує внутрішній користувач.** Кроки підпорядковуються видимості проєкту завдання. Користувач може працювати з кроками завдання, якщо виконується **будь-яка** з умов:
- проєкт завдання видимий усім внутрішнім працівникам (або також порталу),
- користувач підписаний на проєкт завдання,
- користувач підписаний на завдання,
- користувача призначено на завдання.

Крім того, завдання має належати одній із дозволених компаній користувача (або не мати компанії).

**Шаблони глобальні.** Вони не мають поля компанії, тому всі компанії в мультикомпанійній базі бачать однакові шаблони.

Щоб призначити роль: `Settings` → `Users & Companies` → `Users` → оберіть користувача → рівень доступу **Project** (**User** або **Administrator**).

## 11. Обмеження

| Тема | Обмеження |
|---|---|
| Сповіщення | Під час зміни статусу кроку не надсилаються листи, повідомлення в чаті, активності чи нагадування. |
| Призначення | Кроки не мають окремого виконавця чи терміну. За весь чек-лист відповідають виконавці завдання. |
| Повторне відкриття кроків | Немає кнопки, щоб повернути крок **Done** або **Cancelled**; натомість змініть клітинку **Status** вручну. |
| Звітність | Немає окремих звітів, дашбордів чи PDF. Можна використовувати стовпець **Checklist Progress**, середнє значення в групуванні та фільтр **With Checklist**. |
| Час кроків | **Started On** / **Done On** зберігаються для кожного кроку, але не показуються в стандартних поданнях. |
| Мультикомпанійність | Шаблони не прив'язані до компанії. Усі компанії мають спільний список шаблонів. |
| Зміна шаблону | Щойно будь-який крок розпочато, виконано чи скасовано, змінити шаблон повторним вибором у полі не можна. Використовуйте кнопку **Replace Checklist**. Заміна видаляє поточні кроки разом зі статусами, і скасувати її неможливо. |
| Оновлення шаблонів | Зміни шаблону не переносяться в завдання, які вже його використовують. Так задумано. |
| Очищення поля Checklist | Очищення поля **Checklist** (у завданні без прогресу) не видаляє вже скопійовані кроки. За потреби видаліть їх на вкладці **Checklist**. |
| Видимість меню | **Project → Configuration → Checklists** розміщено в стандартному меню налаштувань, яке Odoo показує лише адміністраторам проєктів. |
