Product Kind — Manufacturing Classification

Turns product classification into a system your production and sales history can actually trust: reclassify a product any time, and while its bill of materials updates immediately, every already-confirmed sale order line and manufacturing order keeps the classification it had the moment it was confirmed — so past documents never quietly change meaning.

Key Features

Hierarchical Kind Catalog

A draggable multi-level tree with List, Kanban and Form views, plus route type and manufacturing mode per kind.

Different From Product Category

Unlike Odoo's built-in Category — accounting-focused, with no history protection — Product Kind is production-focused and freezes itself onto confirmed documents instead of silently rewriting history.

Live Product Link

Products and bills of materials always reflect a kind's current classification — reclassify anytime and everything downstream updates immediately.

Frozen Sale & MO Snapshots

Confirming a sale order or creating a manufacturing order freezes the kind at that moment, so history never silently changes.

Manager-Only Snapshot Edits

Once frozen, only a Product Kind Manager can correct a snapshot — enforced at the model level, even against direct API or import writes.

Subtree Smart Buttons

Jump from any kind to the Products, BoMs, Sale Lines and Manufacturing Orders across its entire subtree, counts included.

Snapshot-Aware Reporting

Sales Analysis groups by Product Kind and Route Type using the same snapshot-first, live-fallback rule as the rest of the module.

Safe Archiving & Deletion

A kind can't be archived while active sub-kinds exist, and only a leaf kind can be deleted — no accidental subtree wipeouts.

Known limitations

  • The manufacturing-order snapshot inherits from a sale order line only if your installation links MOs to sale lines; otherwise every MO snapshots the product's current kind at creation.
  • The manufacturing-mode field records intent for reporting and automation — it doesn't itself alter Odoo's procurement routes.
  • Smart-button counters are computed on read (not stored) and reflect the current database state each time the form is opened.
