Sale Warehouse Auto Fulfillment

One Confirm click: delivery validated, invoice created, invoice posted

Standard Odoo stops at the delivery order. Someone still has to open the transfer and click Validate, come back to the sales order and click Create Invoice, then open the draft invoice and click Confirm.

This module adds three checkboxes to the warehouse form. When they are on, pressing Confirm on a sales order shipped from that warehouse runs the whole chain automatically — invisibly, behind the button your team already uses. No new menu, no new screen, no new model.

Key Features

  • Ship Automatically (auto_ship) — validates the delivery in full: all lines, full ordered quantity, no backorder.
  • Create Invoice Automatically (auto_invoice_create) — runs exactly what the manual Create Invoice button runs, so each product keeps its own invoicing policy.
  • Confirm Invoice Automatically (auto_invoice_confirm) — posts the invoice this run has just created.
  • All-or-nothing safety — the whole run, including the order's state change, sits inside one database savepoint.
  • "Nothing to invoice" is never an error — the step is skipped silently and a note is added to the order's chatter.
  • Auditable failures — every failed run is written to ir.logging through an independent transaction, so it survives the rollback.
  • Zero footprint when off — with the switches off, action_confirm() is a plain pass-through to standard Odoo.

How it works

  1. Go to Inventory › Configuration › Warehouses and open a warehouse. The three checkboxes sit next to the Short Name field.
  2. Create a quotation as usual and make sure its Warehouse points at that warehouse.
  3. Click Confirm. The delivery smart button shows Done, the invoice counter goes up and the invoice is already Posted.
  4. If a real error occurs — a required lot/serial, a missing receivable account — everything is rolled back. The order stays a quotation and a blocking message names the stage and the reason.

Good to know

Automatic shipping performs no stock availability check — negative stock is intended behaviour, so only enable it on warehouses with trusted stock figures. Delivery is all-or-nothing (no partial shipping), invoices are posted but never emailed, and the setting is strictly per warehouse: there is no per-order override and no exception list.
