Employee Salary Advance

Ask, approve, pay, recover — the whole advance in one record

An employee needs money before payday. This module turns that conversation into a tracked record: it checks the request against your company policy, disburses it through a real posted account.payment, and pushes the outstanding balance onto the next payslip as an ADV_DEDUCT deduction. When the balance reaches zero, the advance closes itself.

Key Features

Policy-driven eligibility

A percentage of the monthly wage, an optional absolute ceiling, and a switch for holding more than one open advance. Four figures — Monthly Salary, Maximum Allowed, Already Outstanding and Available — are computed live on the form, before the amount is even entered.

Wage resolved by date, not by guesswork

Both the wage and the "is there an active contract" check read the hr.version in force on the request date. Backdate a request and the module reads the contract that was in force then, so the two answers can never disagree.

Checks that an import cannot bypass

Submit and Approve run the same @api.constrains, and the workflow methods check the HR group themselves — hiding a button is not the only thing standing between an employee and an approval.

A real payment, or nothing at all

The Pay wizard creates and posts an outbound account.payment to the employee's work contact. It refuses outright when the disbursement journal is unconfigured or the employee has no work contact — naming the requirement rather than guessing. If posting fails, the whole transaction rolls back: no state change, no orphaned draft payment.

Automatic payroll recovery

A ADV_DEDUCT input line is appended to the next payslip. Confirmation writes back whatever that line actually says — so a payroll officer can spread the repayment by editing the amount — clamped so an advance can never be over-recovered or counted twice.

Multi-company and localized

Policy lives on res.company, backed by a global company record rule. Ships with a full Ukrainian translation.

How it works

  1. Configure once. Under Settings → Employees → Salary Advances, set the maximum percentage, the optional ceiling, and the Salary Advance Journal. Then add the shipped Salary Advance Deduction rule to the salary structures that should recover advances — the module ships the rule but deliberately never attaches it for you.
  2. Record the request. Under Employees → Salary Advances, pick the employee, enter the amount and the reason. The reference (ADV/00001) is assigned on save and the eligibility block updates as you type.
  3. Submit and approve. Both steps re-check the amount against Available, the one-open-advance policy, and the contract in force on the request date.
  4. Pay. The wizard posts the payment and moves the advance to Paid in a single transaction. Smart buttons open the payment and its journal entry — and fail closed for users without accounting rights.
  5. Let payroll do the rest. The deduction appears on the next payslip; confirming it records the recovery and closes the advance once the balance reaches zero.
