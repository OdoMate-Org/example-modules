Audit Trail

Who did what, to which record, and what the value was before

Audit Trail records create, update, delete, export and view activity on the models you nominate, storing the old and new value of every changed field. Watch settings are declared per model and per company, so nothing is recorded until you confirm a rule. Models without an active rule pay only a cached set-membership check, which is what keeps the rest of the system fast. It records only — it never blocks, approves, or reverses an action.

Key Features

Watch rules you control

One audit.rule per model per company, with a draft/active workflow. Uniqueness is enforced by a real database constraint, and a second rule for the same pair is refused with a message naming the existing one. Setting a rule back to draft stops recording without deleting a single line of history.

Full or light detail

Full detail stores the old and the new value of every changed field. Light detail skips the extra read of the record and stores new values only. The trade-off is spelled out on screen next to each option, not buried in documentation.

Deletion snapshots

When a watched record is deleted, its field values can be stored on the event itself — because the record is gone. Excluded fields are scrubbed out of the snapshot too, not just out of the change lines.

Export and view tracking

Export events record exactly which record ids left the system, with a View Exported Records button that reopens that precise set. Optional view tracking records one event per row displayed, for both list views and single-record opens.

Working sessions and screens

Events are grouped into per-user sessions using an inactivity timeout, and linked to the screen they came from. Opening a session shows its screen trail and its full story in order.

Exclusions and retention

Excluded users produce no event at all — ideal for a noisy integration account. An opt-in scheduled job deletes expired events in self-re-triggering batches, so a first clean-up on a large history never holds one long transaction open.

How it works

  1. Go to Audit Trail → Configuration → Watch Rules and create a rule for the model you want to watch — Contacts, for example.
  2. Pick Full or Light detail and tick the actions to record: Creations, Updates, Deletions, Exports, Views.
  3. Optionally list Excluded Users whose activity should never be recorded, and Excluded Fields that must never appear in stored values.
  4. Press Confirm. Recording starts immediately.
  5. Review activity under Audit Trail → Logs, search individual field changes across every watched model under Field Changes, or open a record and press View Logs.

Honest limitations

There is no tamper-proofing: audit administrators can delete recorded history. This is an activity record, not a sealed vault. The module does not approve, block, alert, or chart — it records, lists, groups and searches. View tracking creates one event per displayed row and is off by default for that reason.

Full documentation, including the performance notes and the complete limitations list, ships with the module at doc/USER_GUIDE.md.
