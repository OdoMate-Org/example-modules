# Посібник користувача: Панель застосунків (Apps Dashboard)

> Персональний головний екран «My Apps»: квадратні плитки для кожного застосунку Odoo, який ви вже можете відкрити, з улюбленими зверху, пріоритетними застосунками, які адміністратор показує першими для всіх, іншими — впорядкованими за частотою використання, і можливістю перетягувати плитки, якщо потрібен повний контроль.

## 1. Що робить цей модуль

Модуль Apps Dashboard додає екран **My Apps**, на якому кожен доступний вам застосунок показано великою квадратною плиткою з іконкою та назвою. Застосунки, якими ви користуєтеся найчастіше, можна закріпити зірочкою, щоб вони завжди були першими; плитки можна відфільтрувати, ввівши частину назви; а панель можна зробити першим екраном після входу в систему — для себе особисто або, якщо ви адміністратор, для всіх у базі даних.

Адміністратори також можуть налаштувати загальний для всієї бази даних список **Priority Apps** (Settings → General Settings), щоб застосунки, які компанія вже вирішила вважати «завжди доступними», показувалися першими для кожного користувача. Застосунки, які не є улюбленими й не входять до пріоритетного списку, впорядковуються за тим, як часто кожна людина їх насправді відкриває, а будь-хто може перетягувати плитки, щоб встановити власний порядок, якщо потрібен більший контроль.

Панель ніколи не надає нового доступу: вона показує лише ті застосунки, які вже є у вашому стандартному меню застосунків Odoo.

| Можливість | Деталі |
|---|---|
| Плитки застосунків | Одна плитка на кожен застосунок верхнього рівня, який ви можете відкрити: іконка, назва, індикатор пріоритету та зірочка у верхньому правому куті. |
| Улюблені | Натисніть зірочку, щоб закріпити застосунок. Закріплені застосунки показуються в розділі **Favorites** над усім іншим. Улюблені є особистими й зберігаються у вашому користувачі. |
| Пріоритетні застосунки | Адміністратори обирають застосунки, у певному порядку, які завжди йдуть першими для кожного користувача серед тих, що не є улюбленими (Settings → General Settings → My Apps Dashboard → **Manage Priority Apps**). |
| Порядок за використанням | Застосунки, які ви не зробили улюбленими, не позначили пріоритетними й не перетягували вручну, впорядковуються за тим, як часто ви особисто їх відкриваєте, — ті, які ви використовуєте найбільше, автоматично підіймаються нагору. |
| Перетягування | Перетягніть будь-яку не улюблену плитку на нове місце. Цю позицію зберігає лише перетягнута плитка; плитки, які ви не переміщували, зберігають автоматичний порядок за пріоритетом і використанням навколо неї. |
| Пошук | Поле **Search apps...** фільтрує плитки за назвою під час введення (без урахування регістру, збіг з будь-якою частиною назви). |
| Відкриття застосунку | Натискання на плитку відкриває застосунок так само, як стандартне меню застосунків, і зараховується до порядку використання цього застосунку. |
| Головний екран | У **My Preferences** параметр **Home Screen** дозволяє вибрати між **Default Menu** та **Apps Dashboard**. Адміністратори також можуть встановити панель як типовий головний екран одразу для всіх користувачів. |

## 2. Де знайти його в Odoo

Після встановлення в головному меню застосунків з'являється новий застосунок верхнього рівня **My Apps**. Він стоїть у кінці списку застосунків (послідовність 9999), тому не замінює ваш звичайний стартовий застосунок, доки панель не буде обрано (вами або адміністратором) як головний екран, і видимий усім внутрішнім користувачам.

- **My Apps** — відкриває панель. Також можна перейти безпосередньо за адресою `/odoo/my-apps`.
- **My Apps → Priority Apps** — лише для адміністраторів. Керування загальним для всієї бази даних списком застосунків, закріплених першими для всіх.
- **Меню аватара (вгорі праворуч) → My Preferences → Home Screen** — визначає, чи відкриває Odoo панель після вашого власного входу.
- **Settings → General Settings → My Apps Dashboard** — лише для адміністраторів. Встановлення панелі як типового головного екрана для всієї бази даних і швидка кнопка **Manage Priority Apps**.

## 3. Початкове налаштування

Для звичного використання налаштування не потрібне. Кожен внутрішній користувач може відкрити **My Apps** одразу після встановлення. Кожен користувач бачить лише свої застосунки, свої улюблені та власний порядок за використанням.

> 💡 Якщо модуль встановлено з демонстраційними даними, **Employees**, **Project** і **Timesheets** (ті, що встановлені) вже налаштовані як загальні для бази даних Priority Apps, а в адміністратора додатково закріплені як особисті улюблені ці ж застосунки плюс, якщо встановлені, **Invoicing**, **Time Off**, **Recruitment**, **CRM**, **Sales** і **Purchase**. Якщо жоден із кандидатів на пріоритет не встановлено, пріоритетні застосунки не налаштовуються, а улюблені натомість закріплюють **Settings**.

Адміністратори, які хочуть, щоб панель була стартовим екраном для всіх, або хочуть налаштувати список Priority Apps, роблять це один раз у **Settings → General Settings → My Apps Dashboard** — див. [розділ 6](#6-пріоритетні-застосунки-порядок-за-використанням-і-перетягування-плиток) і [розділ 7](#7-панель-як-головний-екран).

## 4. Робота з панеллю My Apps

**Шлях:** `My Apps`

Угорі екрана розташовані заголовок **My Apps** і поле **Search apps...**, під ними — плитки.

| Елемент | Що він робить |
|---|---|
| Плитка (іконка + назва) | Натисніть будь-де на плитці, щоб відкрити застосунок. Відкриття плитки також зараховується до порядку використання цього застосунку. |
| Зірочка (верхній правий кут плитки) | Порожня зірочка = не в улюблених (підказка **Add to favorites**). Жовта зірочка = в улюблених (підказка **Remove from favorites**). Натискання на зірочку не відкриває застосунок. |
| Значок кнопки (верхній лівий кут плитки) | Показується, коли застосунок входить у загальний для бази даних список Priority Apps і ви не перемістили його вручну. |
| Розділ **Favorites** | Показується лише тоді, коли у вас є хоча б один улюблений застосунок, до якого ви ще маєте доступ. Завжди першим. |
| Розділ **All Apps** | Усе, що не є улюбленим: спочатку пріоритетні застосунки (у порядку, встановленому адміністратором), потім решта — за частотою використання. Кожна перетягнута вами плитка залишається там, куди ви її поклали, а інші розташовуються навколо неї. Заголовок **All Apps** з'являється лише тоді, коли над ним показано розділ **Favorites**. |
| Перетягування | Коли поле пошуку порожнє, перетягніть будь-яку плитку в **All Apps** на нове місце. Там закріплюється лише перетягнута плитка; сусідні зберігають автоматичний порядок. Під час активного фільтра пошуку перетягування вимкнено. |
| **Search apps...** | Фільтрує обидва розділи одночасно. Очистіть поле, щоб знову побачити всі плитки (і знову дозволити перетягування). |

Повідомлення, які ви можете побачити:

| Повідомлення | Значення |
|---|---|
| **No apps available yet** — «You do not have access to any application. Ask your administrator to grant you access rights.» | Ваш користувач не може відкрити жодного застосунку. Попросіть адміністратора надати вам права доступу. |
| **No app matches your search.** | Жодна назва застосунку не містить введеного тексту. Змініть або очистіть пошук. |
| **This app is no longer available to you.** (попередження) | Ви натиснули зірочку застосунку, доступ до якого втратили після завантаження сторінки. Панель перезавантажується, і плитка зникає. |

## 5. Улюблені

**Щоб закріпити застосунок:** натисніть порожню зірочку на його плитці. Зірочка стане жовтою, а плитка переміститься в розділ **Favorites**.

**Щоб відкріпити застосунок:** натисніть жовту зірочку. Плитка повернеться в **All Apps**, де її розташування визначається порядком пріоритету / використання / перетягування, описаним у [розділі 6](#6-пріоритетні-застосунки-порядок-за-використанням-і-перетягування-плиток).

Правила:

- Улюблені є особистими. Закріплення застосунку не впливає на інших користувачів.
- Закріпити можна лише застосунки, які ви бачите на панелі. Сервер відмовляє в закріпленні застосунку, який вам не дозволено відкривати.
- Якщо згодом ви втратите доступ до закріпленого застосунку (наприклад, адміністратор вилучить вас із групи), застосунок просто зникне з вашої панелі. Улюблений запис не видаляється: якщо доступ відновлять, застосунок автоматично знову з'явиться в **Favorites**.

## 6. Пріоритетні застосунки, порядок за використанням і перетягування плиток

Плитки в **All Apps** (усе, що не є особистим улюбленим) упорядковуються так, від першого до останнього:

1. **Пріоритетні застосунки** — застосунки, які адміністратор закріпив для всієї бази даних, у встановленому ним порядку, доки ви самі не перемістили цю плитку вручну.
2. **Ваші найбільш використовувані застосунки** — серед решти першим іде застосунок, який ви особисто відкриваєте найчастіше, потім наступний за частотою і так далі. Застосунок, який ви ще ніколи не відкривали, стоїть позаду будь-якого застосунку, відкритого хоча б раз.
3. **Ваш власний порядок перетягування** — щойно ви перетягнете будь-яку плитку в **All Apps**, ця плитка (і надалі будь-яка перетягнута вами плитка) зберігає точну позицію, яку ви їй надали, попереду автоматичного порядку за пріоритетом/використанням для цієї плитки. Застосунки, які ви ще не переставляли особисто, усе ще підпорядковуються правилам 1 і 2 навколо тих, що ви переставили.

**Керування загальним для бази даних списком Priority Apps** (лише адміністратори):

**Шлях:** `Settings → General Settings → My Apps Dashboard → Manage Priority Apps` або `My Apps → Priority Apps`.

1. Відкрийте **Manage Priority Apps**. Ви побачите список із ручкою для перетягування та стовпцем **App**.
2. Натисніть **New**, оберіть кореневий застосунок у полі **App** і збережіть. Його додано в кінець списку (послідовність встановлюється після поточного останнього рядка). Список **App** пропонує лише застосунки, які можуть з'явитися на панелі: кореневі застосунки, видимі у звичайному меню застосунків (поза режимом розробника), окрім самого **My Apps**. Кожен збережений рядок має заголовок із назвою свого застосунку.
3. Перетягуйте рядки за ручку, щоб змінити порядок, у якому всі бачать пріоритетні застосунки.
4. Видаліть рядок, щоб перестати вважати цей застосунок пріоритетним для всіх (він усе ще показується в **All Apps**, упорядкований за використанням, як і будь-який інший застосунок).

Пріоритетні застосунки — це загальне для бази даних налаштування: кожен прийнятний користувач бачить ті самі пріоритетні застосунки в тому самому порядку (якщо він особисто не перетягнув цю плитку в іншу позицію на своїй власній панелі). Пріоритетний застосунок з'являється як плитка лише для користувачів, які вже бачать його у своєму стандартному меню застосунків, — пріоритетний список ніколи не надає додаткового доступу.

**Перетягування власних плиток:**

Коли поле пошуку порожнє, перетягніть будь-яку плитку в **All Apps** на нове місце й відпустіть. Браузер показує рух плитки під час перетягування. Новий порядок зберігається миттєво і є особистим для вас — він не змінює те, що бачать інші.

## 7. Панель як головний екран

### Для одного користувача

**Шлях:** меню аватара (вгорі праворуч) → `My Preferences` → поле **Home Screen** (на вкладці **Preferences**, під **Email Signature**; адміністратори також бачать це поле на вкладці **Preferences** у **Settings → Users** для будь-якого внутрішнього користувача)

| Варіант | Результат |
|---|---|
| **Default Menu** | Після входу Odoo відкривається як зазвичай. Якщо вашою домашньою дією (Home Action) була панель, її буде очищено. |
| **Apps Dashboard** | Домашня дія (**Home Action**) вашого користувача встановлюється на панель **My Apps**, тож після входу Odoo відкривається на панелі. |

Натисніть **Save**. Новий головний екран почне діяти після наступного входу або перезавантаження Odoo.

> ⚠️ Якщо адміністратор призначив вам іншу домашню дію (наприклад, воронку продажів), вибір **Default Menu** її не видаляє. Очищається лише домашня дія панелі, встановлена цим параметром. Вибір **Apps Dashboard** замінює будь-яку попередню домашню дію.

### Для всієї бази даних (адміністратори)

**Шлях:** `Settings → General Settings → My Apps Dashboard → Apps Dashboard is the default home screen`

Увімкнення цього перемикача та натискання **Save** одразу встановлює **Home Screen** на **Apps Dashboard** для кожного активного внутрішнього користувача (користувачі порталу й публічні користувачі ніколи не змінюються й не отримують панель як домашню дію) — перезаписуючи індивідуальний вибір кожного на цей момент. Вимкнення й збереження повертає всіх активних внутрішніх користувачів до **Default Menu**. Будь-хто після цього може зайти у власні **My Preferences** й обрати той варіант, який йому особисто подобається; загальне для бази даних налаштування визначає лише те, що відбувається *в момент збереження*, а не постійно діюче обмеження.

Користувач, зареєстрований після того, як ви це увімкнули, починає з типового для бази даних значення; користувач, створений, коли це вимкнено, починає з **Default Menu**, як і раніше.

## 8. Приклад

Анна — менеджерка проєктів. Її користувач може відкрити шість застосунків: **Discuss**, **Calendar**, **Contacts**, **Project**, **Timesheets** та **Employees**. **Settings** немає на її панелі, бо вона не адміністраторка. Адміністратор уже встановив **Project** як загальний для бази даних Priority App.

1. Анна натискає **My Apps**. **All Apps** показує **Project** першим (це пріоритетний застосунок), потім інші п'ять, упорядковані за її використанням — усі рівні нулю, тож зберігається стандартний порядок меню: Discuss, Calendar, Contacts, Timesheets, Employees. Улюблених у неї ще немає, тож окремого розділу **Favorites** немає.
2. Вона натискає зірочку на **Timesheets**. Він переміщується в новий розділ **Favorites** над усім іншим.
3. Протягом кількох наступних днів вона відкриває **Contacts** вісім разів, а **Calendar** — двічі. Наступного разу, коли вона відкриває панель, **All Apps** тепер показує: Project (досі пріоритетний, досі перший), Contacts (найбільш використовуваний), Discuss, Calendar, Employees.
4. Вона вирішує, що хоче бачити **Discuss** одразу після **Project**, незалежно від використання, тому перетягує його плитку на одну позицію вгору. Відтепер **Discuss** зберігає цю позицію, навіть коли її використання інших застосунків змінюється, а Contacts/Calendar/Employees продовжують автоматично переставлятися навколо нього на основі використання.
5. Вона відкриває **My Preferences**, встановлює **Home Screen** на **Apps Dashboard** і натискає **Save**. Після наступного входу Odoo відкривається одразу на **My Apps**.
6. Пізніше адміністратор забирає в Анни доступ до Timesheets. Під час наступного відвідування розділ **Favorites** зникає (інших улюблених у неї немає), а **Timesheets** взагалі зникає з панелі. Коли доступ відновлюють, **Timesheets** повертається в улюблені без повторного закріплення.

## 9. Які застосунки показуються на панелі

Застосунок з'являється на вашій панелі лише за виконання всіх цих умов:

| Умова | Пояснення |
|---|---|
| Це меню застосунку верхнього рівня | Підменю (наприклад, *Sales → Orders*) ніколи не показуються як плитки. |
| Ви бачите його в стандартному меню застосунків | Та сама перевірка, яку Odoo використовує для власного меню застосунків: групи меню та право читання дії меню. Панель показує рівно ті самі застосунки, що й це меню, включно із застосунками без власної дії (натискання на них відкриває їхнє перше підменю, як у стандартному меню застосунків). |
| Це не саме **My Apps** | Панель не показує плитку самої себе. |

Пріоритетний застосунок, якого конкретний користувач не бачить у своєму стандартному меню застосунків, просто ніколи не з'являється як плитка для цього користувача — пріоритетний список ніколи не є джерелом додаткового доступу. Користувачі порталу та публічні користувачі не бачать меню **My Apps**. Якщо такий користувач усе ж звернеться до панелі, він отримає порожній список.

## 10. Ролі доступу

Модуль не створює нових груп безпеки. Він додає дві невеликі внутрішні моделі — `app_dashboard.priority.app` і `app_dashboard.tile` — із власними правилами доступу.

| Хто | Відкрити My Apps | Закріплювати / відкріплювати улюблені | Перетягувати власні плитки | Змінювати власний Home Screen | Керувати Priority Apps / типовим значенням для бази даних |
|---|---|---|---|---|---|
| **Внутрішній користувач** (`base.group_user`) | ✅ | ✅ Власні улюблені, лише для доступних застосунків | ✅ Лише власний порядок | ✅ Власний параметр | ❌ Лише перегляд пріоритетного списку |
| **Адміністратор** (`base.group_system`) | ✅ | ✅ Власні улюблені | ✅ Лише власний порядок | ✅ Власний параметр; також може напряму змінювати **Home Action** будь-якого користувача | ✅ |
| **Користувач порталу / публічний** | ❌ Меню приховано, порожній список | ❌ | ❌ | ❌ | ❌ |

Те, що бачить кожен користувач, повністю залежить від прав, які він уже має в інших застосунках. Щоб дати комусь нову плитку, надайте доступ до відповідного застосунку: `Settings` → `Users & Companies` → `Users` → виберіть користувача → права доступу. Власний порядок плиток і лічильники використання кожної людини (`app_dashboard.tile`) є приватними — ніхто інший не може читати чи змінювати рядки іншого користувача, що гарантується правилом доступу на рівні бази даних, а не лише інтерфейсом.

## 11. Технічна довідка

| Модель | Призначення |
|---|---|
| `res.users` (розширено) | Додає `favorite_app_menu_ids` (Many2many → `ir.ui.menu`) і `home_screen_mode` (Selection: `default_menu` / `apps_dashboard`, за замовчуванням — загальне для бази даних налаштування). |
| `app_dashboard.priority.app` | Один рядок на кожен загальний для бази даних пріоритетний застосунок: `menu_id` (Many2one → `ir.ui.menu`) і `sequence`. Керується із Settings або `My Apps → Priority Apps`. |
| `app_dashboard.tile` | Один рядок на кожного користувача й кожен застосунок, який він відкривав або переставляв: `user_id`, `menu_id`, `open_count` (лічильник використання), `sequence` і `is_manual` (true, щойно користувач перетягнув цю плитку). |
| `res.config.settings` (розширено) | Додає `app_dashboard_default_home_screen` — булеве поле, що зберігається як системний параметр `app_dashboard.default_home_screen` і масово застосовує типовий Home Screen до кожного активного внутрішнього (не порталового) користувача під час збереження. |

| Елемент | Ідентифікатор |
|---|---|
| Клієнтська дія | `app_dashboard.action_apps_dashboard` (тег `app_dashboard.AppsDashboard`, шлях `my-apps`) |
| Меню | `app_dashboard.menu_apps_dashboard_root`, `app_dashboard.menu_app_dashboard_priority_app` |
| Дія/подання Priority Apps | `app_dashboard.action_app_dashboard_priority_app`, `app_dashboard.view_app_dashboard_priority_app_list` |
| Подання налаштувань | `app_dashboard.view_users_form_simple_modif_app_dashboard` |
| Подання Settings | `app_dashboard.res_config_settings_view_form_app_dashboard` |
| Серверні методи | `res.users.get_app_dashboard_data()`, `res.users.toggle_app_favorite(menu_id)`, `res.users.register_app_open(menu_id)`, `res.users.reorder_apps(ordered_menu_ids, moved_menu_id)` |

## 12. Обмеження

| Тема | Обмеження |
|---|---|
| Вміст плитки | Плитки показують іконку, назву, індикатор пріоритету та зірочку. Лічильників у реальному часі, значків чи попереднього перегляду немає. |
| Перетягування | Перетягувати можна лише плитки в **All Apps**; **Favorites** зберігає свій порядок, визначений зірочкою. Під час активного фільтра пошуку перетягування вимкнено. |
| Типове значення для бази даних | Увімкнення перемикача в Settings перезаписує Home Screen кожного активного внутрішнього користувача на той момент (користувачі порталу пропускаються); це не постійно діюча політика, тож користувачі можуть пізніше змінити власне налаштування. |
| Синхронізація Home Action | Якщо адміністратор змінює **Home Action** користувача безпосередньо у формі користувача, вибір **Home Screen** не оновлюється відповідно. |
| Коли набирає чинності | Змінений **Home Screen** застосовується після наступного входу або перезавантаження сторінки, а не одразу. |
| Доступ | Панель ніколи не надає доступу. Застосунку, якого немає на панелі, немає і в стандартному меню застосунків або в списку Priority Apps для цього користувача; це виправляється правами доступу, а не цим модулем. |
| Застарілі улюблені | Улюблені для застосунків, до яких у вас більше немає доступу, приховуються, а не видаляються. Вони залишаються збереженими у вашому користувачі. |
| Облік використання | Відкриття застосунку збільшує простий лічильник на користувача; він не враховує, скільки часу ви провели в застосунку чи що там робили. |
| Інтеграції | Немає інтеграції з якимось конкретним застосунком; модуль працює з будь-якими встановленими застосунками. |
