# Посібник користувача: Product Sample Requests (Запити на зразки продукції)

> Торгові представники запитують зразки продукції для клієнтів, менеджери затверджують і відправляють їх, а Odoo нагадує представнику зв'язатися з клієнтом і рахує, скільки зразків перетворилося на замовлення.

## 1. Що робить цей модуль

Модуль замінює листи й таблиці, через які зазвичай погоджують зразки. Торговий представник створює **Sample Request** (`sample.request`, запит на зразки) для клієнта з одним або кількома товарами та кількостями й подає його. Менеджер з продажу затверджує або відхиляє запит. Коли зразки відправлено, менеджер натискає **Mark as Sent** (Позначити як відправлене), і Odoo планує для представника завдання To-Do через 14 днів. Представник фіксує, чи зробив клієнт замовлення, а меню Reporting показує конверсію «зразок → замовлення» по кожному представнику.

| Можливість | Подробиці |
|---|---|
| Запити зі списком товарів | Customer (Клієнт), Sales Rep (Торговий представник), Reason (Причина), Reason Details (Деталі причини) та вкладка **Products** (Товари: Product, Quantity). Кожен запит отримує номер на кшталт `SR/2026/0001`. |
| Процес погодження | Draft → Submitted → Approved → Sent → Followed Up, а також Rejected і Cancelled. Кожна зміна статусу записується в чаттері. |
| Обов'язкова причина відмови | Кнопка **Reject** (Відхилити) відкриває вікно, де причину вказувати обов'язково. Причина відображається в запиті. |
| Сповіщення менеджерів при поданні | **Submit** створює активність To-Do «Sample request awaiting approval» для кожного користувача з групою **Sample Request / Manager**, тож ніхто не має пам'ятати перевіряти меню Approvals. |
| Автоматичне завдання на контакт | **Mark as Sent** створює активність To-Do «Follow up on sample request» для представника з терміном Sent Date + 14 днів. |
| Фіксація результату | Вікно **Log Outcome** (Записати результат): Ordered / Still Thinking / Not Interested, з можливістю прив'язати Sales Order (замовлення на продаж). |
| Звіт про конверсію | Зведена таблиця та графік за Sales Rep і Status з показниками **Converted** і **Conversion Rate (%)**. |
| Видимість записів | Представники бачать лише власні запити, менеджери бачать усі. |

## 2. Де знайти модуль в Odoo

Після встановлення в головному меню з'являється застосунок **Sample Requests** з такими пунктами:

- **My Requests** (Мої запити): ваші власні запити (фільтр «My Requests» увімкнено за замовчуванням). Відкривається канбан, згрупований за статусом. Доступні також список, форма, зведена таблиця та графік.
- **Approvals** (Погодження, лише менеджери): усі запити зі статусом **Submitted**, які чекають рішення. Створювати запити з цього меню не можна.
- **All Requests** (Усі запити, лише менеджери): усі запити всіх представників.
- **Reporting** (Звітність): зведена таблиця та графік *Sample Request Analysis*, які відкриваються з уже ввімкненим фільтром **Sent or Followed Up**.

## 3. Початкове налаштування

Окрім прав доступу, нічого налаштовувати не потрібно. Сторінки налаштувань модуль не має.

1. Перейдіть у **Settings → Users & Companies → Users** (Налаштування → Користувачі та компанії → Користувачі) і відкрийте користувача.
2. У розділі прав доступу встановіть для **Sample Request** значення **User** (торгові представники) або **Manager** (ті, хто затверджує та відправляє зразки).
3. Збережіть. Застосунок **Sample Requests** з'явиться в меню цього користувача.

| Хто | Яку групу призначити |
|---|---|
| Торговий представник, який запитує зразки | `Sample Request / User` |
| Менеджер з продажу або логіст, який затверджує та відправляє | `Sample Request / Manager` |

> Порада: обліковий запис адміністратора отримує **Sample Request / Manager** автоматично під час встановлення, тож застосунок видно одразу.
>
> Порада: `Sample Request / User` також надає **Sales / User: Own Documents Only** (Продажі / Користувач: лише власні документи), щоб представники могли вибрати замовлення на продаж під час фіксації результату.

## 4. Створення запиту на зразки

**Шлях:** `Sample Requests` → `My Requests` → `New` (Створити)

| Поле | Опис |
|---|---|
| **Reference** (Номер) | Призначається автоматично під час збереження (наприклад `SR/2026/0007`). Лише для читання. |
| **Customer** (Клієнт) | Обов'язкове. Компанія або контакт, який отримує зразки. |
| **Sales Rep** (Торговий представник) | Обов'язкове. За замовчуванням це ви. Змінити його може лише менеджер і лише поки запит у статусі Draft. |
| **Reason** (Причина) | Необов'язкове: Deal in Progress (угода в роботі), New Prospect (новий потенційний клієнт), Existing Customer (наявний клієнт), Trade Show (виставка), Other (інше). |
| **Reason Details** (Деталі причини) | Вільний текст для того, хто погоджує, наприклад «Пілотна партія для тендеру Q3, 2 кольори». |
| Вкладка **Products** (Товари) | Один рядок на товар: **Product** і **Quantity**. Кількість має бути більшою за нуль. |

**Схема статусів:**

```
Draft ──Submit──▶ Submitted ──Approve──▶ Approved ──Mark as Sent──▶ Sent ──Log Outcome──▶ Followed Up
  │                  │
  │                  ├──Reject (потрібна причина)──▶ Rejected
  │                  │
  └──Cancel──────────┴──Cancel──▶ Cancelled
```

Draft = Чернетка, Submitted = Подано, Approved = Затверджено, Rejected = Відхилено, Sent = Відправлено, Followed Up = Опрацьовано, Cancelled = Скасовано.

> Увага: Rejected і Cancelled є остаточними статусами. Щоб спробувати ще раз, відкрийте запит і виберіть **Actions → Duplicate** (Дії → Дублювати). Копія створюється як нова чернетка з тим самим клієнтом, причиною та рядками товарів.

## 5. Основний робочий процес

### Сценарій 1: представник запитує зразки

**Крок 1: заповніть запит.** Виберіть **Customer**, за бажанням **Reason** і **Reason Details**, і додайте принаймні один рядок на вкладці **Products**.

**Крок 2: натисніть Submit (Подати).**
- Якщо вкладка **Products** порожня, Odoo зупинить вас повідомленням «Add at least one product to … before submitting it.» (Додайте принаймні один товар перед поданням).
- Статус зміниться на **Submitted**, і запит з'явиться в меню **Approvals** у всіх менеджерів.
- Кожен користувач із групою **Sample Request / Manager** отримує активність To-Do «Sample request awaiting approval» на цьому запиті з терміном «сьогодні». Це завдання автоматично закривається, щойно будь-який менеджер затвердить або відхилить запит, або представник скасує його — вручну знімати його не потрібно.

> Увага: після подання ви більше не можете змінювати клієнта, причину, представника чи товари. Якщо щось не так, натисніть **Cancel** (Скасувати; доступно в статусах Draft і Submitted), а потім продублюйте запит і виправте копію.

### Сценарій 2: менеджер ухвалює рішення

Відкрийте **Sample Requests → Approvals** і відкрийте потрібний запит.

- **Approve** (Затвердити): статус зміниться на **Approved**, а в полі **Decided By** (Рішення ухвалив) з'явиться ваше ім'я.
- **Reject** (Відхилити): відкриється вікно з обов'язковим полем **Rejection Reason** (Причина відхилення). Натисніть **Reject** у вікні. Статус зміниться на **Rejected**, з'явиться червона стрічка «Rejected», а причина та **Decided By** відображатимуться у формі.

Рішення щодо будь-якого запиту може ухвалити будь-який користувач із групою **Sample Request / Manager**. Погодження не прив'язане до безпосереднього керівника представника.

### Сценарій 3: менеджер відправляє зразки

Коли посилку відправлено, відкрийте затверджений запит і натисніть **Mark as Sent**:

- **Sent Date** (Дата відправлення) заповнюється сьогоднішньою датою. Якщо менеджер уже вказав дату заздалегідь, вона зберігається.
- Статус змінюється на **Sent**.
- Для представника планується завдання To-Do (див. [розділ 6](#6-нагадування-та-результат-контакту)).

Поки запит має статус **Sent**, менеджер може виправити **Sent Date** у формі. Ця зміна **не** переносить уже створене завдання, тож за потреби змініть його термін вручну.

### Видалення

Видалити можна лише запити в статусі **Draft** або **Cancelled**. Для інших статусів з'явиться «Only draft or cancelled sample requests can be deleted.» Замість видалення скасуйте запит, щоб зберегти історію.

## 6. Нагадування та результат контакту

### Нагадування

**Mark as Sent** створює в запиті рівно одну активність:

| Властивість | Значення |
|---|---|
| Тип | To-Do |
| Підсумок | Follow up on sample request |
| Виконавець | **Sales Rep** запиту |
| Термін | **Sent Date** + 14 днів |

Приклад: Sent Date = **3 березня 2026**, отже термін завдання **17 березня 2026**. Представник бачить його в меню активностей (значок годинника) та в чаттері запиту.

### Фіксація результату

У запиті зі статусом **Sent** представник-власник (або будь-який менеджер) натискає **Log Outcome**. Відкривається вікно *Log Follow-up Outcome*:

| Поле | Опис |
|---|---|
| **Outcome** (Результат) | Обов'язкове: **Ordered** (Замовив), **Still Thinking** (Ще думає) або **Not Interested** (Не зацікавлений). |
| **Sales Order** (Замовлення на продаж) | Показується лише для **Ordered**, необов'язкове. Можна вибрати лише замовлення, де клієнтом є клієнт запиту або один з його контактів. Створити нове замовлення звідси не можна. |

Натисніть **Log Outcome**. Odoo:
- змінює статус на **Followed Up** і зберігає **Follow-up Outcome**,
- позначає завдання як виконане з коментарем «Outcome: Ordered» (або вибраним результатом),
- показує зелену стрічку «Ordered», якщо результат Ordered.

> Порада: якщо замовлення ще немає в Odoo, зафіксуйте **Ordered** без замовлення. Пізніше відкрийте запит і заповніть **Sales Order** у формі. Для запитів з результатом Ordered це поле залишається доступним для редагування.
>
> Примітка: **Still Thinking** також закриває запит і його завдання. Повторне нагадування не створюється. Якщо потрібне ще одне нагадування, заплануйте нову активність у чаттері самостійно.

## 7. Звітність і коефіцієнт конверсії

**Шлях:** `Sample Requests` → `Reporting`

Зведена таблиця *Sample Request Analysis* відкривається з такими параметрами:
- **Рядки:** Sales Rep
- **Стовпці:** Status
- **Показники:** **Count** (Кількість), **Converted** (Конвертовано), **Conversion Rate (%)** (Коефіцієнт конверсії)
- **Фільтр:** **Sent or Followed Up** (уже ввімкнено)

Кожен запит зберігає два значення:

| Показник | Значення для одного запиту | Як агрегується у зведеній таблиці |
|---|---|---|
| **Converted** | 1, якщо Followed Up з результатом Ordered, інакше 0 | Сума |
| **Conversion Rate (%)** | 100, якщо Followed Up з результатом Ordered, інакше 0 | Середнє |

Отже, з увімкненим фільтром за замовчуванням:

```
Conversion Rate = замовлені запити ÷ (відправлені + опрацьовані запити) × 100
```

**Приклад розрахунку.** Ганна має 10 запитів у статусі Sent або Followed Up: 2 ще **Sent**, 8 **Followed Up** (3 Ordered, 4 Still Thinking, 1 Not Interested).

| Sales Rep | Count | Converted | Conversion Rate (%) |
|---|---|---|---|
| Ганна | 10 | 3 | (3 × 100 + 7 × 0) ÷ 10 = **30,00** |

> Увага: якщо прибрати фільтр **Sent or Followed Up**, чернетки, відхилені та скасовані запити рахуються як 0 і занижують коефіцієнт. У прикладі додавання 5 чернеток і 1 відхиленого запиту дало б 3 ÷ 16 = **18,75 %**. Тримайте фільтр увімкненим, коли дивитеся на коефіцієнт, або дивіться лише на стовпці **Sent** і **Followed Up**.

Інші корисні фільтри та групування в панелі пошуку: **Pending Approval** (Очікують погодження), **Awaiting Follow-up** (Очікують контакту), **Converted to Order** (Перетворено на замовлення), **Sent Date** (за періодом), а також групування за **Outcome**, **Reason** або **Customer**.

Графік показує стовпчасту діаграму запитів за Sales Rep і Status і тепер пропонує той самий показник **Conversion Rate (%)**, що й зведена таблиця — відкрийте список показників і виберіть **Conversion Rate (%)**, щоб порівняти представників одним поглядом, без зведеної таблиці. Стовпці більше не накопичуються, тож висота стовпця кожного представника порівнюється напряму (накопичене середнє не дало би жодного зрозумілого підсумку).

## 8. Ролі доступу

| Дія | Sample Request / User (представник) | Sample Request / Manager |
|---|---|---|
| Перегляд запитів | Лише власні (Sales Rep = я) | Усі |
| Створення запиту | Так, для себе | Так, для будь-якого представника |
| Редагування запиту / товарів | Лише в статусі Draft | Так, у будь-якому статусі (після Draft форма блокує більшість полів) |
| Submit | Власні чернетки | Будь-які чернетки |
| Cancel (Draft / Submitted) | Власні | Будь-які |
| Approve / Reject / Mark as Sent | Ні | Так |
| Зміна Sent Date у статусі Sent | Ні | Так |
| Log Outcome (у статусі Sent) | Власні | Будь-які |
| Прив'язка Sales Order до запиту з результатом Ordered | Власні | Будь-які |
| Видалення | Власні Draft / Cancelled | Будь-які Draft / Cancelled |
| Меню | My Requests, Reporting | My Requests, Approvals, All Requests, Reporting |

`Sample Request / Manager` включає всі права `Sample Request / User`. `Sample Request / User` включає **Sales / User: Own Documents Only**. У меню Reporting представник бачить статистику лише за власними запитами.

Як призначити ролі: **Settings → Users & Companies → Users** → виберіть користувача → поле доступу **Sample Request**.

## 9. Обмеження

| Тема | Обмеження |
|---|---|
| Кілька компаній | Запити не мають поля Company і правила доступу за компанією. У базі з кількома компаніями менеджери бачать запити всіх компаній. Нумерація спільна для всіх компаній. |
| Коефіцієнт конверсії | Має сенс лише з увімкненим фільтром **Sent or Followed Up** (у Reporting він увімкнений за замовчуванням). Без нього чернетки, відхилені та скасовані запити рахуються як 0. |
| Прив'язане замовлення | Не звіряється з товарами, кількостями чи сумами зразків. Можна прив'язати будь-яке замовлення клієнта або його контактів, зокрема чернетку пропозиції чи скасоване замовлення. |
| Вибір замовлення | Лише замовлення, де клієнтом є клієнт запиту або один з його дочірніх контактів. Замовлення, оформлене на материнську компанію чи стороннього партнера, вибрати не можна. Створити замовлення із запиту не можна. |
| Склад / доставка | Mark as Sent не створює доставку і не рухає залишки. Відправлення відбувається поза цим модулем. |
| Маршрутизація погоджень | Будь-який менеджер може затвердити будь-який запит. Немає рівнів погодження, лімітів сум чи погоджувачів за командами. При поданні кожен менеджер отримує активність To-Do (лист електронною поштою не надсилається). |
| Терміни нагадування | Затримка 14 днів зафіксована в коді. Зміна Sent Date після Mark as Sent не переносить наявне завдання. **Still Thinking** закриває запит без повторного нагадування. |
| Остаточні статуси | Rejected, Cancelled і Followed Up не можна відкрити повторно. Щоб почати знову, використовуйте **Duplicate**. |
| Вартість зразків | Собівартість чи вартість зразків не враховується і не потрапляє у звіти. |
