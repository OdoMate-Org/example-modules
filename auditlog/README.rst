Audit Log

Audit Log records who created, modified, deleted, read or exported which
records on the Odoo models you choose. For every audited operation it stores a
log (user, date, record, operation, HTTP session and request) with one line per
changed field showing the old and new value in readable form. Rules are
configured per model with full or fast logging, user and field exclusions, a
deleted-record snapshot option and a block-or-skip policy for logging failures.
Logs are isolated per company, and an optional scheduled action purges audit
data after a retention period. Built for administrators, auditors and
compliance officers.

Installation
============

To install this module, you need to:

#. Clone or download the module into your Odoo addons path.
#. Update the apps list (Apps → Update Apps List).
#. Search for "Audit Log" (technical name ``auditlog``) and click Install.

The module depends only on ``base``.

Configuration
=============

After installation:

#. Activate the developer mode (Settings → Activate the developer mode).
#. Go to Settings → Technical → Audit → Rules and click **New**.
#. Pick a **Model** (e.g. Contact), a **Type** (Full log / Fast log), the
   operations to log (Log Creates, Log Writes, Log Deletes, Log Reads,
   Log Exports), optionally **Capture Record**, **Users to Exclude** and
   **Fields to Exclude**, and the **On Logging Failure** policy
   (Block the operation / Skip the log).
#. Click **Confirm**. Auditing starts immediately and a **View logs** action
   appears in the Actions menu of the audited model's form. The rule's
   **Logs** smart button opens all logs of its model.
#. Optional: activate the scheduled action **Auto-vacuum audit logs**
   (Settings → Technical → Automation → Scheduled Actions). It ships inactive
   and keeps 180 days by default. To purge immediately, use Settings →
   Technical → Audit → **Delete Old Logs** (Keep Last (Days), Chunk Size).

Assign users to **Auditlog User** (read-only) or **Auditlog Manager** (full)
under Settings → Users & Companies → Users. Settings administrators are
Auditlog Managers automatically.

Usage
=====

#. Navigate to Settings → Technical → Audit → Logs.
#. Filter by Create / Write / Delete / Read / Export, or group by User, Model,
   Method, Company or Date.
#. Open a log to see the **Fields updated** tab (Description, Old value Text,
   New value Text) and the **Technical** tab (session and HTTP request).
#. Example: renaming the contact "Azure Interior" to "Azure Interior SA"
   produces one ``write`` log whose Name line reads
   *Azure Interior* → *Azure Interior SA*.
#. Users in the Access Rights group can search every field change across all
   logs in Settings → Technical → Audit → Log Lines.

For the full step-by-step guide, see ``doc/USER_GUIDE.md``
(also available in Ukrainian ``doc/USER_GUIDE.uk.md`` and Polish
``doc/USER_GUIDE.pl.md``).

Known limitations
=================

* ORM methods of audited models are patched at registry level (same technique
  as ``base_automation``); budget a review or rewrite on each major Odoo upgrade.
* Read logging on high-traffic models is expensive and grows the database fast.
* Fast log cannot show old values (they appear as ``False``).
* The Log Lines menu is a read-only SQL view.
* Logs produced in read-only transactions are written in a separate cursor.
* Changes made through raw SQL, and binary fields, are never logged.
* One rule per model; rules are global (not per company).
* The retention cron is inactive until you enable it.

See ``doc/USER_GUIDE.md`` section "Limitations" for the full list.
